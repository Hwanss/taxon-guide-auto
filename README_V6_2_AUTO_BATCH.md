# TaxonGuru AdSense Recovery v6.2 — 자동분할 정리

## 목적
기존 콘텐츠를 사용자가 매번 Run workflow로 나눠 실행하지 않아도 되도록,
GitHub Actions 예약 실행마다 작은 묶음으로 자동 감사·재작성합니다.

## 기본 동작
- 한국시간 03:17 / 09:17 / 15:17 / 21:17 예약 실행
- 기본 회당 최대 2개 기존 콘텐츠 처리
- 한 실행 최대 50분까지만 작업 후 안전 종료
- 다음 예약 실행에서 남은 작업 자동 이어서 처리
- 기존 재작성 대기 글이 있으면 그것부터 처리
- 대기 글이 없으면 상태가 정확히 `완료`인 기존 글을 감사
- B/C/D 등 재작성 필요 글은 WordPress 초안 전환 → 근거 조사 → KO/EN 재작성 → 자동검수
- 자동검수 통과 후에도 사람 검수용 WordPress 초안으로 유지
- 같은 글의 재작성 재시도는 한 실행에서 반복하지 않고 다음 예약 실행으로 넘김
- Gemini 월 지출한도/429는 콘텐츠 실패 횟수로 계산하지 않음
- WordPress 연결 장애는 다음 예약 실행에서 재시도
- AdSense 복구모드 동안 신규 글 자동발행은 계속 OFF

## 자동 속도 조절
기본값은 회당 2건입니다.
수동검수 대기열이 50건 이상 쌓이면 자동으로 회당 1건으로 낮춰 과도한 대기열 증가를 막습니다.
35건 이상이면 최대 2건으로 제한합니다.

현재 남은 `완료` 35건 기준으로 연결/API 장애가 없으면 하루 최대 약 8건 수준으로 순차 처리됩니다.
실제 처리량은 각 글의 재작성 필요 여부와 API 응답시간에 따라 달라집니다.

## Google Sheet 자동 복구
이전 버전에서 URL/예약일/오류 계열 열에 잘못 남은 `649` 값을 실행 시작 시 자동 정리합니다.
대상 열:
- 공개URL
- 예약일
- 오류
- EN_공개URL
- EN_예약일
- 영문오류

## 자동 준비도 검사
기존 `완료` 및 재작성 대기열이 모두 소진되고,
`기존수동검수대기` 등 사람 검수 대기 건수도 0이 되면 다음 예약 실행에서
`site_readiness.py`가 자동 실행됩니다.

즉 운영 순서는 다음과 같습니다.

기존 글 자동분할 정리 → 사람 검수 대기 → 사용자가 WordPress에서 확인 후 공개 → 자동 상태 동기화 → 준비도 자동 검사

## 사용자가 해야 할 일
1. v6.2 파일을 GitHub 저장소에 덮어쓰기
2. Commit / Push
3. 이후 평소에는 Run workflow를 누르지 않아도 됨
4. WordPress의 수동검수 대기 초안을 시간 날 때 확인 후 공개
5. `파이프라인상태`에서 남은 수량 확인

## 수동 실행이 필요할 때
GitHub Actions → `TaxonGuru AdSense Recovery v6.2` → Run workflow

- `auto`: 평소 자동 운영과 동일
- `cleanup`: 기존 정리만 강제 진행
- `readiness`: 준비도 즉시 검사
- `status_only`: 변경 없이 상태만 확인

회당 처리 건수는 1~4건을 선택할 수 있지만 기본값 2건을 권장합니다.
