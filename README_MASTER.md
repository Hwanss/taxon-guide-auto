# TaxonGuru 마스터 자동 운영 v4

기존 공개 글을 감사한 뒤 문제가 있는 글을 임시글로 숨기고, 자동 재작성·검수를 통과하면 기존 예약글 뒤의 다음 빈 순번에 한국어와 영어 글을 예약합니다. 기존 자료 정리가 끝난 뒤에만 신규 `대기` 주제를 작성하고, 대기 주제가 부족하면 주제 목록도 자동 보충합니다.

## 사용자가 직접 상태를 바꿀 필요가 없습니다

기존에 `기존비공개완료`로 바뀐 행은 마스터 컨트롤러가 자동으로 처리합니다.

```text
기존비공개완료
→ 기존재작성대기
→ 기존재작성중
→ 기존한영재예약완료
→ 예약일 실제 공개
→ 기존한영수정완료
```

학명 또는 기존 `WP_POST_ID`가 없어 자동 복구가 불가능한 행만 다음 상태로 남습니다.

```text
기존비공개보류
```

따라서 `기존비공개완료`를 다시 `완료`로 직접 변경하지 마십시오. 다시 `완료`로 변경하면 감사 과정이 중복될 수 있습니다.

## 재작성된 글의 예약 방식

기존 게시물을 즉시 공개하지 않습니다. WordPress에 이미 예약된 글의 날짜를 확인한 뒤 다음 빈 시간에 넣습니다.

```text
기존 예약 글: 7월 29일 09:30 / 18:30
재작성 글 1: 7월 30일 09:30 / 18:30
재작성 글 2: 7월 31일 09:30 / 18:30
```

- 한국어: 오전 09:30
- 영어: 오후 18:30
- 같은 시간에 예약 글이 있으면 자동으로 다음 날짜로 이동
- 기존 한국어 URL과 `WP_POST_ID` 유지
- 기존 영어 글 ID가 있으면 해당 글을 갱신
- 영어 글이 없으면 새 영어 글 생성 후 한·영 연결

## 자동 처리 우선순위

```text
1. 기존 예약 글의 실제 발행 상태 동기화
2. 기존비공개완료를 기존재작성대기로 자동 전환
3. 기존재작성대기/재시도 글 1건 재작성 및 다음 순번 예약
4. 상태가 정확히 완료인 기존 공개 글 감사
5. 재작성 예약 글이 실제 공개될 때까지 대기
6. 일반 영문판 실패 글 자동 복구
7. 상태가 대기인 신규 주제 1건 작성
8. 대기 주제가 10건 미만이면 12건 자동 보충
```

`한영예약완료` 상태의 기존 예약 글은 감사 대상에서 제외하고 그대로 보존합니다.

## 감사 판정 후 처리

| 판정 | 처리 |
|---|---|
| A | 공개 유지, `기존검수완료` |
| B/C | 즉시 임시글 전환, `기존재작성대기` |
| D | 기본적으로 임시글 전환 후 재작성 시도 |
| 재작성 성공 | 다음 빈 순번 예약, `기존한영재예약완료` |
| 재작성 실패 | 최대 3회 `기존재작성재시도` |
| 3회 실패 | `기존비공개보류` 상태로 안전 보관 |
| 예약일 실제 공개 | `기존한영수정완료` |

영구 삭제는 자동으로 하지 않습니다. 애드센스 심사에서 숨겨야 하는 글은 WordPress `임시글`로 전환해 복구 가능하게 보관합니다.

## 자동 실행 일정

한국시간 기준 하루 네 번 실행합니다.

```text
03:17
09:17
15:17
21:17
```

기존 정리 단계에서는 감사와 재작성을 반복합니다. 기존 정리가 모두 끝난 뒤 신규 글은 오전 03:17 실행에서 하루 1건만 작성합니다.

## GitHub에 적용할 파일

ZIP 파일 자체를 저장소에 올리지 말고 압축을 푼 뒤 다음 파일을 같은 위치에 덮어씁니다.

```text
pipeline_controller.py
audit_existing_posts.py
main.py
generate_topics.py
requirements.txt

.github/workflows/audit.yml
.github/workflows/schedule.yml
.github/workflows/generate_topics.yml
```

WordPress의 `TaxonGuru Multilingual Bridge` 플러그인과 `setup_site_pages.py`, `setup_pages.yml`은 그대로 유지합니다.

## 첫 실행

파일을 커밋한 뒤 다음 Action만 실행합니다.

```text
TaxonGuru Master Cleanup & Publish
```

권장 입력:

```text
force_phase: auto
legacy_batch_size: 1
force_new_now: false
```

첫 실행이 초록색으로 끝나면 이후에는 직접 실행할 필요가 없습니다.

## 실행하지 않아도 되는 Action

```text
TaxonGuru Bilingual Story Auto-Publish (CONTROLLED)
TaxonGuru Topic Planner (CONTROLLED)
```

두 기능 모두 마스터 Action이 내부적으로 자동 처리합니다. `Create Editorial Pages`도 정책 페이지가 이미 만들어졌다면 다시 실행하지 않습니다.

## 추가되는 시트 열

새 코드가 다음 열이 없으면 자동으로 추가합니다.

```text
재작성시도
정리메모
```

- `재작성시도`: 최대 3회 자동 재시도 횟수
- `정리메모`: 감사·재작성·예약 진행 상태 요약

## 파이프라인상태 탭

Google Sheets의 `파이프라인상태` 탭에서 다음 수치를 확인할 수 있습니다.

```text
기존완료잔여
기존재작성대기
기존재예약대기
기존비공개보류
한영예약완료보존
대기주제
영문재검수
다음작업
오류
```

매일 GitHub 로그나 WordPress를 확인할 필요는 없습니다. `기존비공개보류`가 증가하거나 `오류`가 지속될 때만 해당 행을 확인하면 됩니다.
