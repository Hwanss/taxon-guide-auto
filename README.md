# TaxonGuru 한·영 자동 예약발행 v4.4

이번 버전은 다음 두 문제를 수정합니다.

1. 영어 본문이 `[1]` 형식의 인용표시를 4개 이상 만들지 못해 계속 초안으로 남는 문제
2. WordPress 본문 이미지가 화면 폭을 거의 가득 채워 지나치게 크게 보이는 문제

## 주요 변경사항

### 영어 글 자동 복구

Google Sheets 상태가 아래 중 하나이면 신규 주제보다 먼저 처리합니다.

- `한국어예약/영문검수필요`
- `한국어완료/영문검수필요`

이때 한국어 예약글은 다시 작성하거나 예약일을 바꾸지 않고, 영어 글만 재작성·검수·예약합니다. 기존 `EN_POST_ID`가 있으면 같은 영문 초안을 갱신합니다.

### 영어 인용표시 보정

모델이 다음과 같이 다른 형태로 쓴 인용표시를 자동으로 `[번호]`로 정규화합니다.

- `【1】`
- `[Source 1]`
- `(Reference 1)`
- `<sup>1</sup>`
- `[1, 2]`

영어 본문 자체는 정상인데 인용표시만 부족한 경우에는:

1. 인용표시 전용 AI 보정
2. 검증된 사실과 연결된 출처 번호를 이용한 결정적 보정

순서로 처리합니다. 긴 영어 글 전체를 단순히 폐기하고 다시 생성하지 않습니다.

### 본문 이미지 크기

기본값:

- 최대 너비: `720px`
- 최대 높이: `520px`
- 모바일: 화면 너비에 맞춰 자동 축소
- 가운데 정렬
- 원본 비율 유지

GitHub Actions에서 아래 값으로 조절할 수 있습니다.

```yaml
BODY_IMAGE_MAX_WIDTH: '720'
BODY_IMAGE_MAX_HEIGHT: '520'
```

더 작게 표시하려면 예를 들어:

```yaml
BODY_IMAGE_MAX_WIDTH: '640'
BODY_IMAGE_MAX_HEIGHT: '460'
```

로 변경합니다.

영문만 재시도할 때 기존 한국어 예약글의 본문 이미지 크기도 자동으로 다시 적용합니다.

## GitHub에 교체할 파일

압축파일 자체를 저장소에 올리지 말고 압축을 푼 뒤 아래 파일을 같은 위치에 덮어씁니다.

```text
main.py
requirements.txt
.github/workflows/schedule.yml
```

WordPress의 `TaxonGuru Multilingual Bridge` 플러그인은 기존 버전을 그대로 사용합니다.

## 지금 실행하는 방법

현재 시트 상태가 `한국어예약/영문검수필요`라면 상태를 `재작성`으로 바꿀 필요가 없습니다.

1. GitHub에 v4.4 파일을 커밋합니다.
2. `Actions`로 이동합니다.
3. `TaxonGuru Bilingual Story Auto-Publish`를 엽니다.
4. `Run workflow`를 실행합니다.

정상 실행 로그 예시:

```text
영문 전용 재작성 시작
기존 게시물 본문 이미지 크기 조정 완료
영문 본문 생성
영문 인용 복구
영문 자동 검수
영문 예약 복구 완료
```

정상 처리 후 시트 상태는 다음과 같이 바뀝니다.

```text
한국어예약/영문검수필요
→ 영문재작성중
→ 한영예약완료
```

## 파일별 역할

- `main.py`: 연구, 한·영 작성, 검수, 인용 보정, 이미지 업로드, WordPress 예약
- `requirements.txt`: Python 패키지
- `.github/workflows/schedule.yml`: GitHub Actions 실행 및 이미지 크기 설정
- `wordpress-plugin/taxonguru-multilingual-bridge.zip`: 기존 설치용 플러그인

## 주의사항

- 기존 한국어 예약글은 영문 전용 재시도 과정에서 본문 이미지 크기만 조정됩니다.
- 영어 글이 품질점수, 분량, 출처, 이미지 자리표시자 조건까지 모두 통과해야 예약됩니다.
- 대표 이미지는 테마 설정에 따라 목록이나 글 상단에서 크게 보일 수 있습니다. 이번 크기 설정은 본문 안에 들어가는 이미지에 적용됩니다.

## v4.5: 다국어 브리지 오탐지 방지

이 버전은 플러그인이 활성화되어 있어도 호스팅 방화벽·보안 플러그인·캐시가
`/wp-json/taxonguru/v1/status` 요청을 일시적으로 막아 "설치되지 않음"으로 오판하던 문제를 수정합니다.

확인 순서:

1. 공개 status 경로를 인증 없이 확인
2. 인증 포함 재확인
3. `?rest_route=/taxonguru/v1/status` 대체 경로 확인
4. WordPress REST 네임스페이스 확인
5. 최종 한·영 연결 시 전용 경로 실패하면 core posts의 등록된 meta 필드로 양방향 연결

워크플로의 `BRIDGE_PREFLIGHT_STRICT` 기본값은 `false`입니다. 사전 status 확인 실패만으로
전체 글 생성을 중단하지 않으며, 최종 게시물 메타 연결까지 실패할 때만 명확한 오류로 중단합니다.
